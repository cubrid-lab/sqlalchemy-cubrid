# Known failures for the SQLAlchemy dialect compliance suite (test/test_suite.py)
#
# Purpose: this manifest lets the official SQLAlchemy suite GATE CI (see #380)
# while tolerating the documented set of currently-failing tests. conftest.py
# reads this file and applies a strict xfail to each listed node id: a listed
# test that FAILS is xfailed (tolerated), but a listed test that PASSES becomes
# an XPASS -> a hard failure, forcing the manifest to be trimmed. Any NEW
# failure not in this list fails CI.
#
# Node ids are version-agnostic w.r.t. the CUBRID server: the live suite
# parametrizes class names with a server-version suffix (e.g.
# ...Test_cubrid+cubrid_11_4_6_1963); conftest.py strips that suffix before
# matching, so entries here use the bare class name.
#
# BASELINE IS SQLALCHEMY-VERSION-SPECIFIC. SQLAlchemy changes suite
# parametrization between releases (e.g. the ObjectKind flag string ordering in
# ComponentReflectionTest.test_get_multi_columns changed between 2.0.36 and
# 2.0.53), so the node ids here are a snapshot. This baseline was captured on
# **SQLAlchemy 2.0.53** against a clean CUBRID 11.4 database, and the gating CI
# cell pins `sqlalchemy==2.0.53` for that reason. A SQLAlchemy bump requires
# recapturing this baseline (run the suite, diff the failures). See #380.
#
# Each group links to the follow-up issue that tracks the real fix. Removing an
# entry (fixing the bug) is the goal; adding one requires a linked reason.
