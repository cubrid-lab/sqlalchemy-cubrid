# 릴리즈 노트 작성 규칙

공개 GitHub Release는 커밋 로그를 그대로 나열하는 공간이 아니라 사용자가 변경사항을 확인하는 문서입니다.
이 저장소에서 검증한 형식을 다른 CUBRID Lab 프로젝트로 확대할 수 있지만, 각 프로젝트의 배포 절차는 유지합니다.

## 표준 구성

GitHub Release 제목은 태그와 완전히 같아야 합니다(예: v1.12.3).
본문에는 사용자 영향 요약 한두 문장을 먼저 작성하고, 내용이 있는 표준 레벨 3 섹션만 다음 순서로 둡니다.

1. Upgrade notes
2. Added
3. Changed
4. Deprecated
5. Removed
6. Fixed
7. Security
8. Performance
9. Documentation
10. CI
11. Tests

마지막에는 Full Changelog 비교 링크를 정확히 하나 둡니다.
빈 섹션은 생략합니다. 특정 테스트의 실패만으로 데이터베이스 또는 드라이버 기능이 지원되지 않는다고 단정하지 않습니다.

## 변경사항과 작성자

- Conventional Commit 제목만 복사하지 말고 실제 변경 대상과 사용자 영향을 설명합니다. 수동 작성 항목과 자동 생성 항목이 중복되면 통합합니다.
- 확인된 PR이 있으면 진짜 PR 링크를 사용합니다. 이슈 링크를 PR처럼 표시하거나 단순 참조를 자동 종료로 표현하지 않습니다.
- 변경사항 끝에 실제 기여가 확인된 PR 작성자를 `by @username`으로 표기합니다. 공동 작성자는 PR·커밋 이력을 검토해 인정합니다. 이슈 작성자나 담당자로부터 기여자를 추측하지 않습니다.
- 저장소에서 해당 작성자의 최초 병합 기여가 확인된 경우 `by @username (first contribution 🎉)`을 사용합니다. 과거 이력을 확인할 수 없다면 축하는 생략합니다.
- 조직 소속과 외부 기여자를 구분하지 않고 동일하게 인정하며, 자동화 봇을 인간 기여자로 표시하지 않습니다.
- 별도의 Contributors 또는 New Contributors 섹션을 만들지 않습니다. 증명 가능한 작성자가 없다면 작성자 표기를 생략합니다.

예시(가상의 PR 번호와 작성자):

### Fixed

- **Connections** — Corrected reconnect handling (PR #123) by @alice.
- **Types** — Fixed integer conversion (PR #124) by @bob (first contribution 🎉).

### Documentation

- **Examples** — Clarified setup instructions (PR #125) by @charlie.

## Markdown 줄바꿈

Markdown 인라인 링크, 이슈 참조, 기여자 표시, 백틱 기술 식별자를 기계적으로 강제 줄바꿈하거나 재배치하지 않습니다.
문장은 소프트 래핑할 수 있지만 연결된 문장은 같은 변경사항 항목 안에 있어야 합니다.

특히 `#123` 또는 `# 123`으로 시작하는 줄은 금지합니다. 과거 MkDocs 렌더링에서 이러한 줄이 제목처럼 해석된 사례가 있습니다.
한 개의 논리적 변경사항 안에 정확한 Markdown PR·이슈 링크를 기록합니다.
링크 텍스트와 URL을 줄바꿈으로 분리하거나, 의도하지 않은 공백 두 칸의 강제 줄바꿈을 넣거나,
`by @username`을 별도 줄에 두지 않습니다.
릴리즈 PR에서 CHANGELOG를 합성한 뒤 `scripts/check_release_note_wrap.py` 및 회귀 테스트로 검증합니다.

## Release Please와 검토

릴리즈 준비 워크플로는 release-please가 생성한 `RELEASE_CHANGELOG.md` 자체를 변경하지 않습니다.
임시 사본의 커밋을 병합 PR과 연결하고, 해당 저장소에 앞서 병합된 PR을 검색하여 확인된 기여자만 추가한 뒤
`CHANGELOG.md`를 합성합니다. 기여자 확인에 실패하거나 모호하면 임의로 표시하지 않습니다.
검토자는 릴리즈 PR에서 중복, 설명 정확성, 마이그레이션 안내, 작성자 및 공동 작성자, 최초 기여 여부를 확인합니다.
단지 포맷 테스트를 위해 새 릴리즈를 발행하지 않습니다.

## 기존 릴리즈

기존 릴리즈 일괄 정비는 별도 검토된 일회성 작업으로만 수행합니다.
모든 공개 릴리즈 본문을 먼저 정확히 백업하고 버전별 수정 전후 차이와 기여자 증거를 검증합니다.
기존 날짜, 태그, 제목, 사전 릴리즈 상태, 첨부 파일 및 배포 패키지는 변경하지 않습니다.

`CHANGELOG.md`를 기준 문서로 유지합니다. 현재 코드로 과거 내용을 재생성하지 않고,
과거의 기술적 사실과 릴리즈 날짜를 지키면서 검토된 PR에서 섹션을 정리합니다.
해당 PR이 병합된 뒤에만 승인된 본문을 GitHub Release에 버전별로 동기화하고,
원격 본문이 외부에서 수정되었으면 덮어쓰지 않습니다.
준비 PR만 만들었는데 전체 과거 릴리즈를 수정했다고 주장하지 않습니다.
