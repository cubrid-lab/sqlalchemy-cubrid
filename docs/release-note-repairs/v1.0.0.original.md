## sqlalchemy-cubrid 1.0.0 — First Stable Release

### Stability Guarantee

The public API is frozen. Breaking changes will only occur in major version bumps (2.0+).

### Supported Environments

| Component | Versions |
|-----------|----------|
| Python | 3.10, 3.11, 3.12, 3.13, 3.14 |
| CUBRID | 10.2, 11.0, 11.2, 11.4 |
| SQLAlchemy | 2.0–2.1 |
| Alembic | >=1.7 |

### Highlights

- Full SQLAlchemy 2.0–2.1 dialect with statement caching and PEP 561 typing
- SQL compilation: SELECT, JOIN, CAST, LIMIT/OFFSET, window functions, MERGE, ON DUPLICATE KEY UPDATE
- Complete schema reflection: tables, views, columns, PKs, FKs, indexes, unique constraints, comments
- Alembic migration support
- CUBRID-specific types: MONETARY, OBJECT, SET, MULTISET, SEQUENCE
- Two driver options: `cubrid://` (CUBRIDdb) and `cubrid+pycubrid://` (pure Python)

### What's New in 1.0.0

- **Bug fixes**: `visit_join` signature mismatch, `sqlalchemy.sql.util.warn` API
- **Type annotations**: Full coverage across all modules (mypy: 280 → 0 errors)
- **Documentation**: Explicit "SQLAlchemy 2.0–2.1" compatibility, Compatibility Matrix in README
- **Dependency**: pycubrid optional dependency updated to `>=1.0,<2.0`
- Development Status: Beta → Production/Stable

### Known Limitations

- `RETURNING` clauses not supported (CUBRID limitation)
- No `Sequence` support (CUBRID uses `AUTO_INCREMENT`)
- Native `BOOLEAN` not available (mapped to `SMALLINT`)
- Lateral joins, JSON type, and writable CTEs not supported
